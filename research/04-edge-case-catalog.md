# 04 - Edge-case catalog

Every trap we have observed or verified while writing and reading xlsx files, each tied to the fixture that
reproduces it and to the diff category the oracle reports. The table is rendered from
`fixtures/edge-cases.json` (entries) and `fixtures/manifest.json` (fixture tags); the prose
around it is hand-written.

_Accurate as of 2026-09-12. Regenerate with `research/regenerate.sh`._

## How to read it

- **Family** groups the traps: Strings, Numbers, Dates, Cells, Structure, Container, Jetstream (contracts
  the current app depends on).
- **Seen in** names the generator or reader that exhibits the behaviour, as observed in the oracle run.
- **Expected behaviour** is what a correct engine does; where Excel itself was consulted (read-only Excel
  oracle, `oracle/excel/`), the status says so.
- **Diff categories** produced by `oracle/diff.mjs` map onto entries as follows: `control-chars-stripped` →
  EC-XML-CONTROL-CHARS; `escape-sequence-mangled` → EC-XML-ESCAPE-*; `crlf-normalized` → EC-CRLF-NORMALIZED;
  `whitespace-trimmed` → EC-XML-SPACE-PRESERVE; `date-tz-offset-shift` / `temporal-mismatch` on the office-kit
  golden → EC-DATE-SERIAL-EPOCH-UTC-FIELDS; `dst-gap-shift-1h` → EC-DATE-DST-GAP; `historical-tz-offset-shift` →
  EC-DATE-HISTORICAL-TZ-OFFSET; `time-only-has-date-part` → EC-TIME-ONLY-HAS-DATE-PART; `date-as-serial` →
  EC-DATE-1900-LEAP-BUG (serial 60) or EC-DATE-DETECTION-VIA-NUMFMT; `error-as-text` → EC-ERROR-CELL-AS-TEXT;
  `formula-dropped` → EC-FORMULA-CACHED-ERROR; `cell-missing` on the openpyxl golden → EC-CONTROL-CHARS-REJECTED
  and EC-FORMULA-LIKE-TEXT-WRITTEN-AS-FORMULA; `blank-vs-empty-string` → EC-BLANK-VS-EMPTY-STRING.

## Notes per family

### Strings

The `_xHHHH_` escape is the single most mishandled rule. Excel is the arbiter: it decodes `_x0001_` to the
control character, shows `_x0041_` for the correctly escaped `_x005F_x0041_`, and decodes office-kit's
`_x005F_x005F_x0041_` to `_x005FA` - the same result SheetJS produces - so a literal `_x005F_x0041_` needs
every underscore that starts an escape-shaped run escaped, including the one shared by two runs. Carriage
returns must be escaped too (`_x000D_`) because an XML parser normalizes a raw CR away; SheetJS's reader then
collapses `\r\n` to `\n` regardless. Jetstream's Salesforce long-text and JSON-blob cells routinely contain
CRLF, tabs and occasionally control characters, so these are not theoretical.

Formula-looking text is a security item as much as a fidelity one: openpyxl and LibreOffice's CSV import
turn `=cmd|calc` into a formula, and Excel then repairs the file. Every JS writer in the survey keeps it as
text; a replacement engine must never infer formulas from user data.

### Dates

Three independent conventions collide: (1) the file stores a serial (days since 1899-12-30 with the Lotus
leap-year bug), (2) the library maps it to a JS Date using either local fields or UTC fields, and (3) the
application interprets the Date. SheetJS uses UTC fields on read (`numdate`) but converts to local in
`sheet_to_json`, and local fields on write; office-kit uses UTC fields in both directions. Feeding a
local-midnight Date to office-kit therefore writes the host's UTC offset into the file (Excel shows
`7:00:00 AM`), and time-only values become negative serials that Excel renders as `########`. The fix is a
boundary conversion, not a library change, but it must be in the adapter and in the tests. Pre-1900 dates
(Salesforce allows 1700) have no Excel representation at all and must be written as text.

### Numbers

Excel displays 15 significant digits; the file may carry 17. `1.7976931348623157E+308` is a legal
xsd:double that office-kit drops and openpyxl turns into `inf`. Negative zero does not survive.

### Structure and container

Every writer surveyed fails the Open XML SDK validator on `CT_Font` child order, and LibreOffice writes a
column width above the schema maximum; Excel and LibreOffice open all of them. The validator is therefore a
strictness gate for our own output, not a compatibility predictor. The shipped multi-object template is a
Google Sheets export with data descriptors, `[Content_Types].xml` last, extension-less `xl/metadata` and
`xl/commentsmeta*` parts, and VML notes - a compact reminder to resolve parts through rels only.
