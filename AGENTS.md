# AGENTS.md

`@jetstreamapp/simple-excel` is a streaming, dependency-free xlsx reader and writer for browsers and Node.
The non-negotiables, in priority order: files we write open cleanly in every mainstream spreadsheet app;
files from every mainstream app read correctly; memory stays flat however large the file; it is fast.
Read `research/11-build-plan.md` before changing anything: it is the contract every module is built to.

## Layout

| Path                | What                                                                                                                                                                                                          |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `src/`              | The library. Browser-first: **no Node globals, no `node:` imports, no DOM** beyond `TextEncoder`/`TextDecoder`, `CompressionStream`/`DecompressionStream` and a duck-typed `Blob`. Zero runtime dependencies. |
| `src/node/`         | The `@jetstreamapp/simple-excel/node` entry: file sources and sinks. The only place `node:` imports are allowed.                                                                                              |
| `src/**/__tests__/` | Unit tests, co-located with the module they cover.                                                                                                                                                            |
| `test/`             | Integration suites: corpus reads, golden bytes, round trips, hostile inputs, SheetJS parity, memory.                                                                                                          |
| `fixtures/`         | The fixture corpus and `manifest.json` (sha256 + provenance for every file). `npm run fixtures:check` must pass.                                                                                              |
| `oracle/`           | Compatibility oracle: SheetJS, office-kit, openpyxl, calamine, Open XML SDK validator, LibreOffice, Excel (AppleScript). Local pre-release gate.                                                              |
| `bench/`            | Benchmark harness (`npm run bench`); our adapters are `bench/engines/simple-excel.mjs` and `simple-excel-zlib.mjs`, and they need `npm run build` first.                                                      |
| `research/`         | Format primer, library landscape, edge-case catalog, compatibility matrix, performance baseline, reference architecture, ADRs, build plan. 04/05/06 are generated by `npm run research:regenerate`.           |
| `docs/`             | Docusaurus site with its own `package-lock.json`.                                                                                                                                                             |

## Rules

- **The catalog is the arbiter.** Escaping, date and container rules live in `research/02-format-primer.md` and
  `research/04-edge-case-catalog.md`; most entries were verified against Excel. When a test disagrees with your
  intuition, the catalog wins.
- **Streaming is the design, not an option.** Writers push bytes to a sink as rows arrive and never hold a
  worksheet or an unbounded shared-string table (ADR-001). Readers pull rows through an async iterator.
- **Deterministic output.** With `deterministic: true` the writer's bytes are reproducible (fixed zip timestamps and
  docProps dates). The golden-bytes suite depends on it.
- **Classified errors.** Throw `XlsxError` with a `code`, never a bare `Error`. The encrypted-file message must contain
  the words `password-protected`.
- **Hot-path discipline.** No per-cell object allocation, no regex per cell, no string concatenation past the chunk
  boundary. Measure with `npm run bench` before and after any change to the writer or reader core.
- Every exported symbol has an explicit type (`isolatedDeclarations`). No `any` in `src/`.
- Prefer verbose names over single letters (except `i`). Always use braces on `if`.

## Commands

```sh
npm test                    # unit + integration (vitest)
npm run test:corpus         # corpus, golden-bytes, hostile and parity suites only
npm run typecheck && npm run lint && npm run format:check
npm run build               # esbuild bundles (esm + cjs, core + node entry) and declarations
npm run fixtures:check      # manifest sha256 drift
npm run oracle -- --tag kind:golden --label <label>    # local only: Excel, LibreOffice, python venv
npm run build && npm run bench -- --engines sheetjs,simple-excel --sizes 1k,10k,100k
npm run size               # bundle-size gate: dist/esm/index.mjs <= 40 KB brotli
npm run research:regenerate
```

Local tooling that is not on CI: `.generated/venv` (python readers, `oracle/python/requirements.txt`), LibreOffice
under `/Applications`, Microsoft Excel with Automation permission (`oracle/excel/PERMISSIONS.md`).

## Formatting and linting

**Always run `npm run format` and `npm run lint` after any change** and fix what lint reports. oxfmt settings are in
`.oxfmtrc.json`, oxlint settings in `.oxlintrc.json` (scoped overrides for `scripts/`, `oracle/`, `bench/`,
`fixtures/` and tests; prefer fixing code over adding overrides). The `.githooks/pre-commit` hook blocks commits
that fail either check. Use conventional commit messages.

## Types and build

`tsconfig.json` sets `isolatedDeclarations`, so every export needs an explicit type annotation. `npm run typecheck`
checks the whole tree including tests and tooling (`tsconfig.typecheck.json`); `npm run build` emits the bundles
and declarations for `src/`. The root package is CommonJS (the vitest config is `vitest.config.mts`).
**Do not add `"type": "module"` to package.json.**

## Testing expectations

- Every module ships unit tests covering each format rule it owns; use catalog ids (`EC-...`) as test names.
- Writer changes keep `test/golden-bytes` green or update snapshots deliberately (`UPDATE_GOLDENS=1`) after a
  validator and oracle pass.
- Reader changes keep every corpus fixture at its recorded verdict (`test/corpus`).
- Before a release, run the full oracle locally and commit the results folder.

## Changelog and releases

Keep `CHANGELOG.md` `[Unreleased]` accurate: its headings decide the bump (`### Breaking Changes` major,
`### Added`/`### Deprecated` minor, `### Changed`/`### Removed`/`### Fixed`/`### Security` patch). Releases are cut
from `main` by CI via `npm run release` (see `scripts/release.mjs`). `scripts/derive-increment.mjs`,
`scripts/release.mjs`, `.githooks/pre-commit` and the workflows are shared verbatim with
[soql-parser-js](https://github.com/jetstreamapp/soql-parser-js); keep the copies in sync.
