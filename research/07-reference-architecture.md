# 07 Reference architecture

The streaming xlsx library we would build if hand-rolling, and the rubric any candidate engine (currently `@office-kit/xlsx`) is scored against in `10-office-kit-evaluation.md`.

_Accurate as of 2026-09-11 (branch chore/xlsx-hand-roll)._

_Design as proposed on 2026-09-11, before the build. The shipped library is `@jetstreamapp/simple-excel`; its
authoritative API is `src/types.ts` and `docs/docs/`. Divergences: `strings` defaults to `'inline'` (ADR-001
addendum) and `xl/sharedStrings.xml` is written only under `'auto'`/`'shared'` when something was interned;
duplicate zip entries are rejected (`ZIP_DUPLICATE_ENTRY`); the inflate guard is a byte cap, not a ratio; zip64
`'auto'` keys off `rowCount`; the reader is `openWorkbook` with `XlsxError` codes; crc32 is slicing-by-16; column
styles (`<col style>`) are supported._

Working name `@jetstreamapp/xlsx`. Zero runtime dependencies. Targets: Chrome 121+, Firefox 120+, Safari 16.4+, Node 24, module Web Workers, Electron renderer and main, MV3 extension pages. Claims about Excel behavior that the oracle has not yet confirmed are marked "(verify)".

## 1. Package layout and module boundaries

One package with subpath exports: `.` (browser/worker-safe core plus facade), `./node` (fs sink, `FileHandle` source, `zlib.createDeflateRaw` with a `level`), `./zip` (the streaming zip alone, which can replace JSZip for the Permission Manager CSV bundle), `./internal` (primitives for tests and the oracle, not semver-stable).

Rules for the core: no `window`, `document`, `FileReader` or `URL.createObjectURL`; only `TextEncoder`, `TextDecoder`, `CompressionStream`, `DecompressionStream`, `AbortSignal` and, in adapters only, duck-typed `Blob`. The library never accepts a foreign-realm `ReadableStream`, `WritableStream` or `Blob` on its hot path: inputs are `Uint8Array` chunks or a `RandomAccessSource`, outputs are `Uint8Array` chunks, and the library instantiates its own compression streams and pumps them with `getWriter()`/`getReader()` exactly like `createGzipEncoder` in `libs/shared/ui-data-history/src/lib/file-store/gzip-utils.ts`. Library tests run in vitest `environment: 'node'`; Jetstream specs keep their Node `Blob` shim.

## 2. Write pipeline (constant memory)

```ts
const wb = createWorkbookWriter(sink, {
  zip64: 'auto' | boolean, strings: 'auto' | 'inline' | 'shared', compression: 'deflate' | 'store',
  deterministic: true, signal, onProgress, onCellTruncated,
});
const ws = wb.addSheet(name, { columns?: { width? }[], freeze?: { rows, cols }, autoFilter?: boolean, header?: CellValue[], headerStyle?: StyleId, rowCount?: number });
await ws.writeRow(values: CellValue[], styles?: StyleId[] | StyleId); // a cached resolved promise unless a flush happened
ws.merge(r1, c1, r2, c2);
await ws.close();          // </sheetData>, autoFilter, mergeCells; one sheet open at a time
const result = await wb.close(); // SST, styles, workbook, rels, content types, docProps, central directory
```

- Byte path: `writeRow` appends fragments to a `string[]` and a char counter; at 64 Ki chars (256 Ki is the alternative to measure) the builder is joined once, encoded with `TextEncoder.encode()`, CRC32 and the uncompressed byte count are updated on the plain chunk, the chunk goes to the `Deflater`, and the drain loop coalesces compressed output before calling `sink.write()`. Awaits happen only on flush boundaries (every 300 to 800 rows); back-pressure propagates sink to deflater `writer.ready` to the `writeRow` promise. No per-cell objects.
- Part order, preferred: a static `[Content_Types].xml` first using `<Default Extension="xml" ContentType="…spreadsheetml.worksheet+xml"/>` plus `<Override>`s for the five fixed-name parts, so the sheet count need not be known up front (verify with the Excel oracle on day one). Fallback: content types last, which Google Sheets and ExcelJS streaming already do and which Excel accepts because it resolves parts through the central directory (verify). Then `_rels/.rels`, docProps, the sheets, `xl/sharedStrings.xml`, `xl/styles.xml`, `xl/workbook.xml` and its rels (including `_xlnm._FilterDatabase` defined names for autofilter sheets), central directory.
- Worksheet element order is hard-coded (`sheetPr? dimension? sheetViews sheetFormatPr? cols sheetData autoFilter mergeCells pageMargins?`); it is the most common cause of the repair dialog.
- Strings: hybrid with a bounded shared-string table, default `'auto'`. Intern only strings of 256 characters or fewer while the table holds fewer than 65,536 unique entries and fewer than 16 Mi characters (both configurable); then freeze the map (repeats still resolve to `t="s"`) and write the rest inline (`t="inlineStr"`). The SST part is always emitted with exact `count` and `uniqueCount`. Worst case is 20 to 40 MB. Mixed `s` and `inlineStr` cells in one sheet must be confirmed across viewers (verify). `strings: 'inline'` is the A/B control.
- Zip64: off by default with a clear `RangeError` when any entry or offset would exceed 32 bits; the facade turns it on when `rowCount x columns > 40M cells` or the size is unknown and large. When on, worksheet and SST entries write version-needed 45 plus the zip64 extended-information extra field in the local header up front and 8-byte data descriptors; small static parts stay 32-bit. Excel repairs a file whose zip64 is declared only in the central directory, so the up-front declaration is not optional. Excel should accept a small zip64 file (verify).
- Up front only: `<cols>` and `<sheetViews>` (freeze) are `addSheet` options; `autoWidth: { sampleRows: 500, min: 8, max: 60 }` buffers that many rows before the prologue, and the facade derives widths from the header row when nothing is given. After the data: `<autoFilter>` and `<mergeCells>` at `ws.close()`. `<dimension>` only when `rowCount` is given; readers derive the range otherwise (Google Sheets omits it).
- Styles registry stays growable for the whole workbook because `styles.xml` is written at `wb.close()`; `StyleId` is the `cellXfs` index returned by `wb.registerStyle(spec)`; header rows default to bold.
- Limits: `cellOverflow: 'truncate' | 'throw'` (default truncate with `...(truncated)` and `onCellTruncated(count)`, which also fixes the Permission Manager path); `NaN` and infinities become `t="e"` `#NUM!`; `-0` becomes `0`; a row past 1,048,576 or a column past 16,384 throws.
- Sheet names: replace `: \ / ? * [ ]` with `_`, strip leading and trailing apostrophes, trim to 31, add ` (2)`, ` (3)` inside the 31-character budget on case-insensitive collision, rename `History` to `History_`, empty to `Sheet1`. Exported so the UI can show the final name.
- Cancellation and progress: `signal` is checked on every `writeRow` and flush; abort tears down the deflater and calls `sink.abort()`. `onProgress({ sheet, rowsWritten, bytesOut })` fires every 5,000 rows and at sheet close, with `bytesOut` from the sink counter.

## 3. Sinks

The internal contract is `ByteSink { write(u8): Promise<void>; close(): Promise<void>; abort(reason?): Promise<void> }`, which is exactly `HistoryWriteStream` / `StreamEncoder` from `gzip-utils.ts`, so the OPFS, File System Access and Electron history stores plug in without an adapter. A `WritableStream<Uint8Array>` is accepted wherever a sink is (wrapped; `write` awaits the writer's `ready`), and `toWritableStream(sink)` exists for the desktop `pipeline(Readable.fromWeb(...), createWriteStream)` path.

| Adapter                                 | Memory profile                                                                                                                                                                                       | 1M x 20 feasibility                                                                                                                                                 |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `BlobCollector` (web default)           | folds chunks into sub-Blobs every 16 to 32 MiB and drops the arrays; Chrome pages Blob data to disk past its in-memory quota, so the JS heap stays flat; hands one `Blob` to the existing `saveFile` | yes; roughly 80 to 300 MB compressed. Firefox and Safari keep Blobs in memory (verify thresholds), so the facade exposes `estimatedBytes` for a UI gate near 500 MB |
| `Uint8ArrayCollector`                   | one contiguous copy at the end, hard `maxBytes` (default 1 GiB)                                                                                                                                      | tests, the sync `prepareExcelFile` shim, extension and canvas                                                                                                       |
| `HistoryWriteStream`                    | constant; OPFS worker, FSA `createWritable`, Electron IPC already stream                                                                                                                             | yes; "export to Data History" and desktop exports without a Blob                                                                                                    |
| `showSaveFilePicker().createWritable()` | constant, disk-backed; Chromium only; must be requested inside the user gesture before generation starts                                                                                             | yes                                                                                                                                                                 |
| Electron IPC to `fs.createWriteStream`  | renderer to preload `createFileWriteStream(name)` to main; chunks batched to 256 KiB or more before crossing IPC                                                                                     | yes; replaces the `will-download` Blob interception for large exports                                                                                               |
| `./node` fs                             | `FileHandle.write` or a `Writable` wrapper; swaps in `zlib.createDeflateRaw({ level })` because the platform `CompressionStream` exposes no level (verify); level 1 is 2 to 3x faster                | API server, benchmarks, CI oracle                                                                                                                                   |

The real browser ceiling is the source data, not the writer: a million Salesforce records held as JS objects is 1 to 3 GB of heap. The writer therefore consumes an `AsyncIterable` of rows so a later phase can feed it from the Bulk API result stream or an IndexedDB cursor, which is what lifts the 500,000-row CSV-only rule.

## 4. Read pipeline

`openSpreadsheet(input: ArrayBuffer | Uint8Array | Blob | File | string, opts)` sniffs the first bytes and returns a discriminated result:

| Magic                      | Result                                                                                                                                                                                                                                                                                                                                                                                   |
| -------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `50 4B 03 04`              | zip; must resolve an `officeDocument` relationship to a workbook part. A `mimetype` entry starting `application/vnd.oasis.opendocument` gives "This is an OpenDocument (.ods) file. Open it in Excel or LibreOffice and save as .xlsx."; a `.docx`/`.pptx` gives "This file is not a spreadsheet."; `50 4B 05 06` gives "The file is empty."                                             |
| `D0 CF 11 E0 A1 B1 1A E1`  | CFB; scan the first 64 KiB for the UTF-16LE stream name `EncryptedPackage`. Present: `EncryptedWorkbookError` whose message contains the literal `password-protected` ("This workbook is password-protected. Remove the password in Excel and save it again as .xlsx."). Absent: `LegacyFormatError` ("This file is a legacy Excel format (.xls). Open it in Excel and save as .xlsx."). |
| `<?xml`, `<html`, `<table` | "SpreadsheetML 2003 XML and HTML exports are not supported; save as .xlsx or .csv."                                                                                                                                                                                                                                                                                                      |
| anything else              | `{ kind: 'text', text, encoding }` after BOM detection (UTF-8 decode with a latin1 retry). The library does not parse CSV; Jetstream routes text to papaparse. This replaces SheetJS's silent CSV-from-bytes handling for Electron open-with `.csv` and Drive `alt=media` downloads.                                                                                                     |

Binary-string inputs (the gapi picker) are converted with a charCode loop until the pickers are refactored to hand bytes (replace `InputReadGoogleSheet.workbook: XLSX.WorkBook` with `SpreadsheetSource = { name; bytes: ArrayBuffer | Blob }`, which is also transferable to a worker). Dropping legacy formats removes `cpexcel.full.mjs` and its extension CSP workaround.

Opening an xlsx touches no sheet data:

1. Zip: find EOCD in the last 64 KiB + 22 bytes, then the zip64 locator and EOCD if present; parse the central directory into `Map<name, entry>` with names normalized (`\` to `/`, leading `/` stripped); duplicate names: last wins with a warning.
2. `[Content_Types].xml`: Defaults plus Overrides, matching Transitional and Strict content-type strings.
3. `_rels/.rels`: the `officeDocument` relationship (type matched by URI suffix so `purl.oclc.org` types resolve); absolute and relative targets both handled; fallback `xl/workbook.xml`.
4. `xl/workbook.xml`: ordered sheet list `{ name, sheetId, rId, state }` and `workbookPr/@date1904`; defined names ignored.
5. `xl/_rels/workbook.xml.rels`: each sheet's part (worksheet vs chartsheet by content type), styles part, SST part. Missing styles means no date cells; missing SST means `t="s"` cells yield `''`.
6. `styles.xml`: custom `numFmts` and `cellXfs[i].numFmtId` into a `Uint8Array isDateByXf`.
7. SST: parsed lazily on the first row iteration into a `string[]` preallocated from `uniqueCount`; each `<si>` flattens direct `<t>` and `<r><t>` runs, skips `<rPh>`, and decodes `_xHHHH_`. One million unique short strings cost 60 to 80 MB; an offsets-into-one-buffer layout stays a v2 option behind the same interface. `maxSharedStringChars` defaults to 256 Mi.

```ts
interface WorkbookHandle {
  sheets: Array<{ name: string; index: number; kind: 'worksheet' | 'chartsheet'; hidden: boolean }>;
  date1904: boolean;
  sheet(nameOrIndex): SheetHandle;
  close(): void;
}
interface SheetHandle {
  rows(opts: { startRow?: number; maxRows?: number; mode: 'array' }): AsyncIterable<CellValue[]>;
  rows(opts: { startRow?: number; maxRows?: number; mode: 'object'; headerOptions? }): AsyncIterable<Record<string, CellValue>>;
  toObjects(opts): Promise<{ rows; headers; truncated: boolean }>;
  head(rowCount: number): Promise<Map<string, RawCell>>; // A1-keyed; cancels the inflate stream after rowCount
}
```

Row parsing: inflate, decode with a streaming `TextDecoder`, push through the tokenizer (or a specialized `sheetData` lexer with a generic fallback), and run a small state machine (`inRow`, `curRow`, `curCol`, `curType`, `curStyle`, `inV`, `inIs`, `inF`, `textBuf`) that materializes a value at `</c>` and yields the row at `</row>`; rows are batched per decoded chunk so the async boundary is per 64 KiB, not per row. Rules: a missing `<row r>` is previous row + 1; a missing `<c r>` is previous column + 1; no `t` means number (`+text` fast path, `NaN` keeps the raw string), then `isDateByXf[s]` turns the serial into a `Date`; `t="s"` indexes the SST (out of range gives `''`); `t="inlineStr"` flattens `<is>`; `t="str"` is a string; `t="b"` is `v === '1'`; `t="e"` is a `CellError`; `t="d"` is ISO 8601 to `Date`; `<f>` is skipped unless `formulas: 'text'`; an empty `<v/>` is null; `decodeCellText` runs only when the text contains `_x`. Limits on rows and columns are enforced.

Object mode reproduces the `sheet_to_json` contract: header is the first row of the range; blank headers become `__EMPTY`, `__EMPTY_1`, …; duplicates become `Name_1`, `Name_2`; `blankRows: false` skips rows with no non-empty cell; `defval: ''` fills missing cells; numbers and booleans stay typed; dates are `Date` objects; no trimming. `skipEmptyHeaders: true` drops `__EMPTY*` columns properly, which turns the lowercase `__empty` no-op into an explicit fix. `rows({ startRow: 4, mode: 'array' })` maps one-to-one onto `sheet_to_json({ range: 4, header: 1 })`; `toObjects({ maxRows })` reports `truncated: true` so a million-row upload stops inflating at row 100,001 for the preview.

v1 requires random-access input: Jetstream always holds the whole file, the SST may follow the sheets in a streaming-produced zip, and WHATWG `DecompressionStream` does not report consumed bytes, so sequential data-descriptor entries would need a JS inflater. Sequential `ReadableStream` input is v2.

Caps: reject `<!DOCTYPE` and `<!ENTITY`; five predefined entities plus numeric references only; per-part inflated cap 1 GiB and total 2 GiB enforced on actual bytes with a ratio guard (abort past 200:1 after 10 MB); SST entries capped at 4M; `maxEntries` 10,000; 64 Mi-character text-node cap; `maxRows` and `maxColumns` on iteration.

## 5. Value and type model

```ts
type CellValue = string | number | boolean | Date | null;
interface CellError {
  readonly error: '#NULL!' | '#DIV/0!' | '#VALUE!' | '#REF!' | '#NAME?' | '#NUM!' | '#N/A' | '#GETTING_DATA' | string;
}
interface RawCell {
  address: string;
  row: number;
  col: number;
  type: 'n' | 's' | 'str' | 'inlineStr' | 'b' | 'e' | 'd' | 'empty';
  value: CellValue | CellError;
  styleIndex: number;
  numFmtId: number;
  isDate: boolean;
  formula?: string;
}
type CellInput = string | number | boolean | Date | null | undefined | bigint;
```

- Write accepts `undefined` (empty) and `bigint` (safe-integer range to number, else string); objects go through `coerce` (default `JSON.stringify`); functions and symbols throw. Read exposes `errors: 'string' | 'null' | 'object'` (facade default `'string'`, so `#N/A` appears as the text users see in Excel).
- Dates on read: `dates: 'local'` (default, matching `cellDates: true`) decomposes the serial into calendar components by integer arithmetic and calls `new Date(y, m - 1, d, h, mi, s, ms)`, so the wall clock the user sees in Excel is the wall clock in JS (including the DST-gap quirk); `'utc'` uses `Date.UTC`; `'serial'` returns the number with `isDate` on the raw cell. Serial to components rounds to the nearest millisecond. Serial 60 (the fictional 1900-02-29) maps to 1900-03-01 with a documented note and serials below 61 shift by one day both ways so real dates round-trip; time-only values (serial below 1) yield a `Date` on 1899-12-30; `date1904` shifts the epoch by 1,462 days. Dates on write mirror this with `dateWriteMode: 'local' | 'utc'`; dates before the epoch are written as ISO strings; an invalid `Date` writes an empty cell.
- Date detection (`numfmt.ts`): built-in ids 14 to 22 and 45 to 47 are dates (locale ids 27 to 36 and 50 to 58 treated as dates, verify); custom codes are scanned once per format, skipping `"…"` literals, `\x` escapes, `[…]` blocks other than elapsed `[h]`, `[mm]`, `[ss]`, and `_x`/`*x` padding, then any of `y m d h s` (case-insensitive) or `AM/PM` means date; `General` and `@` never do. No number-format rendering in v1: Jetstream reads with `rawNumbers: true, cellText: false` and never consumes formatted text, and writes exactly one custom format; a faithful renderer is about 2,000 lines of locale-sensitive code with no consumer. Default `Date` write format is `yyyy-mm-dd hh:mm:ss` (custom id 164 or higher).
- Numbers: `Number.prototype.toString` (shortest round-trip, at most 17 significant digits, which Excel reads exactly); uppercase the exponent marker (Excel writes `1E+21`; lowercase should also be accepted, verify). Lone surrogates are replaced with U+FFFD before encoding. Booleans are `t="b"` with `1`/`0`. Empty values produce no `<c>` unless styled. Formulas are read-only in v1 (cached value; optional formula text on `RawCell`). Rich text is flattened on read and never written.

## 6. Styles v1

```ts
interface CellStyle {
  font?: { bold?: boolean; italic?: boolean; size?: number; color?: string /* '#RRGGBB' */; name?: string };
  fill?: { color: string }; // solid only
  border?: 'thin' | { top?: 'thin'; bottom?: 'thin'; left?: 'thin'; right?: 'thin' };
  alignment?: { horizontal?: 'left' | 'center' | 'right'; vertical?: 'top' | 'center' | 'bottom'; wrapText?: boolean };
  numFmt?: string | number; // format code or built-in id
}
```

Registry: four `Map<canonicalKey, index>` tables plus parallel arrays, seeded so index 0 is always Excel's expectation: `fonts[0]` is Calibri 11 (`<sz val="11"/><name val="Calibri"/><family val="2"/><scheme val="minor"/>`), `fills[0]` is `patternType="none"`, `fills[1]` is `patternType="gray125"` (both mandatory, in that order; Excel repairs files without them), `borders[0]` is the empty five-side border, custom `numFmts` are allocated from id 164 upward with the built-in table consulted first (so `'0.00'` resolves to id 2 without a `<numFmt>`), `cellXfs[0]` is `<xf numFmtId="0" fontId="0" fillId="0" borderId="0" xfId="0"/>`. The `cellXf` key is `${numFmtId}|${fontId}|${fillId}|${borderId}|${h}|${v}|${wrap}`; `apply*="1"` is emitted for each non-default component. `styles.xml` is written at workbook close with `<cellStyleXfs count="1">`, `<cellStyles count="1"><cellStyle name="Normal" xfId="0" builtinId="0"/></cellStyles>`, `<dxfs count="0"/>` and `<tableStyles count="0" defaultTableStyle="TableStyleMedium2" defaultPivotStyle="PivotStyleLight16"/>`. Solid fill is `<patternFill patternType="solid"><fgColor rgb="FFRRGGBB"/><bgColor indexed="64"/></patternFill>`. No theme part is written; fonts and fills use explicit `rgb` colors (Excel should open a workbook without `xl/theme/theme1.xml`; ExcelJS and xlsx-write-stream output does, verify). Per-column default styles cost nothing per row; per-cell overrides arrive as a parallel `StyleId[]`. Colours are not resolved on read in v1. Presets in the facade: `headerBold`, `date('yyyy-mm-dd hh:mm:ss')`, `wrap`, `fill(color)`.

## 7. Compatibility targets and validation oracle

Targets in priority order: Excel 365 (Mac and Windows), Excel 2016+, Google Sheets import, LibreOffice 7+, Apple Numbers; then machine readers openpyxl/pandas, SheetJS 0.20, calamine, Apache POI. Acceptance: opens with no repair dialog and every cell value round-trips.

Local loop (`oracle/`): `@xarsh/ooxml-validator` (bundled Open XML SDK) on every file; Excel (read-only license) opens the file under AppleScript with repair-dialog detection and reads sentinel cells, never saves; Numbers opens and exports; LibreOffice headless converts to CSV (all sheets) and to xlsx; a Python venv reads with openpyxl and python-calamine; SheetJS re-reads with the exact Jetstream options for parity diffs. CI-safe subset: vitest unit and parity tests, the validator, openpyxl and calamine, LibreOffice headless from `libreoffice-calc-nogui` in the CI image, SheetJS round-trip, and golden-byte hash pins for small fixtures already blessed in Excel (output is deterministic: fixed zip mtimes and docProps dates under `deterministic: true`).

## 8. Performance and memory targets

Reference workload "mixed 20" (50% strings of about 12 characters with 30% repeats, 30% numbers, 10% booleans, 10% dates) on an M4 with Node 24 unless stated.

| Scenario                                        | Target                                             | SheetJS baseline |
| ----------------------------------------------- | -------------------------------------------------- | ---------------- |
| Write 100k x 20, Node                           | 1.2 s or less, 120 MB or less heap growth          | 7.1 s / 3.2 GB   |
| Write 1M x 20, Node, fs sink                    | 12 s or less, 250 MB or less, 1.7M cells/s or more | crashes          |
| Write 1M x 20, Chrome worker, rolling-Blob sink | 18 s or less, JS heap 300 MB or less               | crashes          |
| Read 100k x 20 typed object mode                | 1.2 to 1.5 s, 150 to 250 MB (result-dominated)     | 7.5 s / 1.5 GB   |
| Read 1M x 20 array mode, no retention           | 15 s or less, 200 MB plus SST                      | crashes          |
| Read 18M cells (172k x 107) object mode         | completes; 2.5 GB or less retained (the objects)   | crashes          |

Budget reasoning: 1M x 20 is about 850 MB of sheet XML; native deflate at the default level runs 150 to 300 MB/s in Chrome and Node (measure first, it bounds everything), so XML generation must stay under about 4 s (5M cells/s); CRC32 slicing-by-8 adds under 1 s. Floors: 100k rows/s write, 150k rows/s read. Techniques, each a checklist item for code review: column-letter cache and per-row prefix string; number fast path `typeof v === 'number'` then `Number.isFinite` then `'' + v`; escaping fast path as a charCode scan that returns the input unchanged when clean; `_xHHHH_` check only when `_` is seen; `typeof` dispatch ordered string, number, boolean, object; `Date` detected by duck-typing `getTime` (cross-realm safe); no regex on the per-cell path; 64 to 256 Ki-character encode chunks; 1 MiB or larger coalesced sink writes; `TextDecoder` with `{ stream: true }` on read; index-based attribute access in the tokenizer.

## 9. Non-goals for v1 and v2 candidates

v1 excludes: formula writing or evaluation; number-format rendering; hyperlinks, comments, images, charts, tables, conditional formatting, data validation; workbook editing or round-trip preservation; encrypted files (detect and message only); `.xls`, `.xlsb`, `.ods`, SpreadsheetML 2003, HTML; CSV parsing (papaparse stays); theme or indexed colour resolution on read; sequential zip input; a JS inflate/deflate; rich-text writing; column-level styles; print setup; macro passthrough; defined names beyond ignoring them; sheet protection.

v2 candidates, by Jetstream value: data-validation lists for load templates (picklists); hyperlinks (record Id to Salesforce URL); table parts as a nicer autofilter; conditional formatting for status columns; a minimal number-format renderer for previews; source streaming from the Bulk API CSV into the writer; sequential zip reading with a JS inflater; SST offset-buffer layout; comments; a `.xlsb` reader; formula text writing; a worker-hosted facade with transferable results.
